# Propuestas de decisión para F1/F2

Estas son propuestas del implementador del SPIKE, no ratificaciones de arquitectura. Evidencia detallada: [spike.md](spike.md), [parity manifest](evidence/parity-manifest.json), [preview report](evidence/preview-verification.json), [effective Wrangler config](evidence/effective-wrangler.json), and [build proof](evidence/build-proof.json).

| Decisión | Propuesta | Alternativa descartada | Evidencia | Límite que sigue pendiente | Criterio para F2 |
|---|---|---|---|---|---|
| Entrada y delegación | Wrangler apunta a `src/worker.ts`; el Worker usa el handler actual del adaptador y `run_worker_first` cubre solo `/`, Cushing, `/api/*` y `/admin/*`. HTML pasa al handler; Markdown usa Assets en un path separado. | `workerEntryPoint` antiguo del adapter; `run_worker_first: true`; convertir todo a SSR. | Installed `@astrojs/cloudflare/handler` 14.2.6 export/type; Astro build incluyó `src/worker.ts` en `dist/server/entry.mjs`; preview local comprobó home, Cushing y catálogo estático. | Wrangler efectivo agrega `SESSION` local sin ID; nunca probar binding remoto. Las cuatro reglas de worker-first deben revisarse contra la config de producción que F2 genere. | Reproducir build y preview desde un SHA limpio con la config efectiva, comparar rutas HTML/API/redirect y confirmar que el build de Cloudflare usa `npx astro build`. |
| Hook de build | Integración `astro:build:done` lee HTML de `config.build.client`, crea los dos samples y el índice bajo `agent-content/v1/`, y hace fallar el build si el generador falla. | `postbuild`, un paso de build nuevo para Workers Builds o escritura manual posterior al build/deploy. | Build explícito final exit 0; ejecución negativa previa exit 1 con `F0_GENERATOR_FAILURE`; Wrangler dry-run incluyó los 329 assets, incluidos MD e índice. | Dry-run de empaquetado fue sobre el commit anterior a la corrección de validators; el hook y la config no cambiaron después. No se verificó Workers Builds remoto. | En F2, validar el hook en el comando real de Cloudflare Builds, su orden frente al empaquetado y el fallo bloqueante en CI. |
| Selección editorial | Capturar H1 por separado del contenedor de contenido; probar ambas clases de pilar y conservar el contenido de `main article` para artículos. Preservar `<details>`, avisos `aside` y hrefs originales; excluir navegación, runtime, slots de anuncios, TOC repetido y widgets. | Extraer texto desde MDX con regex; borrar todos los `aside`; usar `main.textContent` como única fuente del título. | Siete archivos HTML renderizados, cero sentinels ausentes, 3/2/1/5/5/0/0 avisos por ruta, 7/4/0/8/8/3/4 FAQs y 7/4/3/5/6/6/3 enlaces externos respectivamente. | Las muestras Markdown solo son texto estructurado mínimo. El campo `selector` del manifest resume reglas; F2 debe fijar los selectores por nodo y el serializer definitivo. | Auditar los siete fixtures contra texto DOM visible, revisar cada FAQ completa y advertencia, cotejar URLs externas conservando DOI/PMID/query, y probar el caso sintético sin H1. |
| Caché y validadores | HTML y Markdown mantienen validators distintos. Markdown usa su URL de asset propia; el middleware HTML usa una llave sintética `.../html<path>` sin query. Aplicar If-None-Match a la respuesta delegada/asset según el ETag de la representación elegida. | Compartir una URL de Cache API y confiar solo en `Vary`; reutilizar el ETag de HTML para Markdown; reportar HIT inventado. | Preview: mismo ETag → 304 en la representación elegida; validator cruzado en ambas direcciones → 200 y MIME/body correcto; hashes distintos en ambas variantes; ninguna respuesta mostró `X-Edge-Cache`. | El handler estático resuelve desde Assets antes de ejecutar middleware; por eso el Cache API propio no tuvo un HIT/MISS de runtime en estas rutas. CDN de Cloudflare no verificado. | F2 debe probar Cloudflare Cache API y CDN en una preview aislada, demostrar keys internas por variante y repetir las dos secuencias de alternancia con respuestas observadas, sin query o credenciales en la key. |
| IDs y rutas | Usar `home` y `article--sindrome-cushing-perros-mayores`; índice en `/agent-content/v1/index.json`, Markdown explícito en `/agent-content/v1/documents/<id>.md`, y negociación solo en la home y Cushing del spike. | Crear IDs de cada silo o mostrar un catálogo ficticio de todo el sitio; resolver URL de usuario arbitraria por proximidad. | `index.json` lista solo dos documentos reales; los dos assets se sirven por el ID correspondiente. Home `/` y Cushing devolvieron variantes propias; ruta inventada 404; redirect legacy mantuvo 301/Location. | Tamaño, schema final y regla completa de colisiones de IDs siguen para F2. El spike no prueba el corpus entero como contenido Markdown público. | Ratificar gramática de IDs/aliases y validar cada ID contra inventario canonical antes de generar el catálogo completo. |

Una limitación transversal: el `SESSION` que añade el adapter en su config efectiva es local a la ejecución `wrangler dev --local`; no se configuró ni usó una identidad Cloudflare. El CDN requiere verificación posterior en un entorno aislado de F2.
