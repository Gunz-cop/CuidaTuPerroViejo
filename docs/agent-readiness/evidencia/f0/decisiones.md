# Propuestas de decisión F0

Estas cinco recomendaciones las presenta el implementador para ratificación del coordinador. Son opciones de diseño para F1/F2; F0 no las convierte en arquitectura aprobada ni en implementación de producción.

| Decisión | Recomendación | Alternativa descartada | Evidencia reproducible | Límite y criterio para F2 |
|---|---|---|---|---|
| Entrada y delegación | Conservar el adapter Astro y usar su `@astrojs/cloudflare/handler` como fallback; reservar Worker-first para las rutas de negociación y las exclusiones API/admin ya fijadas. | Sustituir el entrypoint del adapter o enviar todas las rutas al Worker de negociación. | Spike final `926f3c0…` conserva el runtime verificado en `4d0863c…`: build compilado y preview local de 40 checks prueban home/Cushing en ambos formatos y delegación del catálogo Assistant. El commit final del spike solo corrige identidad de una ruta de fixture P4. | La preview fue local y el CDN no se probó. F2 debe validar routing en preview aprobada, preservando seguridad, APIs, admin, redirects y rutas no negociables. |
| Hook de build | Generar las proyecciones después de tener HTML renderizado y antes de empaquetar assets; hacer fallar el build ante error del generador. | `postbuild` separado o escribir artefactos después del build, que no demostraría empaquetado. | `build-proof.json`: build positivo en el spike final; build negativo y dry-run compilado se verificaron en los commits anteriores con el hook/config intactos. | El smoke de Workers Builds de la cuenta no se ejecutó. F2 debe verificar su pipeline exacto y que el fallo impide promover/avisar indexación. |
| Selección editorial | Usar reglas DOM por tipo de página, basadas en HTML renderizado; retener avisos, FAQ y fuentes, y excluir solo chrome/UI/ads/TOC identificados. | Selector compartido de `main.textContent`, conversión regex de MDX o eliminar todos los `aside`. | Siete fixtures permanentes, manifest permanente corregido desde tooling `4d3ab0e…`, y siete fixtures del spike `926f3c0…`; warnings y FAQs conservan texto visible, script/ad fuera del texto; dos tipos de pilar, Cushing, incontinencia y herramientas. | La conversión del spike es un experimento y solo genera home/Cushing. F2 requiere revisar toda la selección de las 28 rutas, fuentes completas, controles de omisión y revisión editorial. |
| Caché y validators | Mantener Markdown en rutas estáticas por ID y distinguir representación en ruta/validator; mantener `Vary: Accept` en URLs negociadas y nunca persistir Authorization. | Reutilizar una URL/validator/cache key de HTML para Markdown o depender de una HIT aparente. | En runtime SHA `4d0863c…`: alternancias HTML↔MD estables, ETags separados, 304 solo en mismo formato y validators cruzados 200; `edgeCache=null`. ASSETS atiende HTML estático antes del middleware, por lo que no se observó una HIT/MISS de la Cache API. | CDN no verificado. F2 debe probar claves, TTL/purga, headers y variantes en preview pública aprobada; no usar query visitante como dimensión de contenido. |
| IDs y rutas | Usar IDs semánticos versionados y allowlist explícita (`home`, `article--<slug>`), con índice JSON que apunta a la ruta Markdown; canonical y ruta pública son datos distintos. | Derivar rutas de entrada arbitraria, ordinales o slug de categoría para identidad persistente. | Contrato `f0-contratos.md`; inventario limpio de 28 documentos; prototipo indexa dos documentos con canonical y `markdownPath` explícitos. El spike final corrige el canonical del fixture de incontinencia a `/higiene-hogar-perros-senior/incontinencia-fecal-perros-senior`. | No se aprobó el schema final, el tamaño ni la migración de IDs del corpus. F2 debe congelar todos los IDs/collisiones/legacy y validar el schema con el inventario completo. |

El coordinador debe ratificar, cambiar o diferir cada recomendación. Las limitaciones anteriores permanecen incluso si se acepta la dirección propuesta.
